Root Cause Analysis

All 85 leaks stem from one structural pattern: BoolEquation stores a raw BoolInterval** array allocated in its constructor but never freed (no destructor). Every DPLL branch creates a copy of BoolEquation via the copy-constructor, which allocates a second cnf[] array — also never freed. The leaked BBV heap-buffers inside each BoolInterval are then indirectly lost through those pointers. The fix is a ~BoolEquation() destructor that calls delete[] cnf.
